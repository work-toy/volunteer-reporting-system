## 1. 项目概述

### 1.1 项目背景

高考是中国高等教育选拔人才的核心机制，每年有上千万考生参加。高考结束后，考生面临志愿填报这一关键环节。志愿填报涉及海量高校信息、专业信息、历年录取分数线等复杂数据，考生和家长往往因信息不对称、缺乏专业指导而面临选择困难，甚至出现高分低就、滑档、退档等遗憾。

为帮助考生科学地填报高考志愿，减少信息不对称带来的决策风险，本项目开发了一套"高考志愿辅助填报系统"，提供高校信息查询、专业信息浏览、估分推荐院校、志愿模拟填报、风险预警及填报技巧指导等功能。

### 1.2 项目定位

本系统定位为《数据库系统》与《团队激励与沟通》课程实训项目，是一个轻量级、易用的高考志愿辅助工具。系统基于 Web 架构，采用前后端分离模式，以 FastAPI + MySQL 构建后端服务，以 Next.js 构建前端界面，提供完整的用户交互体验。

### 1.3 核心业务价值

| 价值点 | 说明 |
|--------|------|
| **数据驱动** | 基于历年录取数据（分数、位次）提供精准推荐 |
| **智能分析** | 通过风险预警算法，自动识别志愿梯度问题 |
| **全流程覆盖** | 从成绩录入、估分推荐、志愿填报到风险检查，形成闭环 |
| **角色分离** | 考生自主填报，管理员维护基础数据，职责清晰 |

### 1.4 项目范围

**包含范围：**

| 模块 | 说明 |
|------|------|
| 用户认证管理 | 用户注册、用户登录、管理员登录、JWT 令牌认证 |
| 高校信息管理 | 高校列表查看（搜索筛选）、高校详情查看、历年录取数据展示 |
| 专业信息管理 | 专业列表查看、专业详情查看 |
| 估分推荐系统 | 基于分数的智能高校推荐（分冲刺/稳妥/保底三级） |
| 成绩录入 | 用户高考成绩和位次的录入与管理 |
| 志愿模拟填报 | 志愿添加、删除、排序、提交、撤销 |
| 风险预警 | 冲稳保比例分析、重复院校检查、分数倒挂检测 |
| 填报技巧 | 填报技巧文章的查看与管理 |
| 留言板 | 用户留言的发布和管理 |
| 后台管理 | 高校/专业/技巧/留言的 CRUD 管理 |

**不包含范围：**

- 真实的高考报名系统对接

- 移动端原生 App
- 实时聊天/客服功能

## 4. 系统技术架构

### 4.1 整体架构

系统采用前后端分离的三层架构：

```
┌─────────────────────────────────────────────────────┐
│                  前端层 (Presentation Layer)          │
│   Next.js 15 (App Router) + React 19 + TypeScript    │
│   Tailwind CSS 4 (毛玻璃设计) + Zustand (状态管理)   │
└───────────────────────┬─────────────────────────────┘
                        │  HTTP API (JSON)
                        ▼
┌─────────────────────────────────────────────────────┐
│                  后端层 (Application Layer)           │
│   FastAPI + SQLAlchemy Async + JWT 认证              │
│   路由: auth / university / major / skill / message  │
│         / score / application (7个模块)               │
└───────────────────────┬─────────────────────────────┘
                        │  SQLAlchemy ORM
                        ▼
┌─────────────────────────────────────────────────────┐
│                  数据库层 (Data Layer)                │
│   MySQL 8.0 + InnoDB + utf8mb4                      │
│   10张表 + 3个SQL脚本 + 1个存储过程 + 1个视图        │
└─────────────────────────────────────────────────────┘
```

### 4.2 技术栈明细

| 层 | 技术 | 版本 |
|----|------|:----:|
| 前端框架 | Next.js (App Router) | 15 |
| UI 库 | React | 19 |
| 编程语言（前端） | TypeScript | — |
| 样式方案 | Tailwind CSS | 4 |
| 状态管理 | Zustand | — |
| 图标库 | Lucide React | — |
| 后端框架 | FastAPI | — |
| ORM | SQLAlchemy (asyncio) | — |
| 数据库 | MySQL | 8.0 |
| 编程语言（后端） | Python | 3.11+ |
| 认证方案 | JWT (python-jose, HS256) | — |
| 包管理（前端） | npm | 8+ |
| 包管理（后端） | uv / pip | — |

### 4.3 认证机制

```
用户登录成功 → 后端颁发 JWT（有效期为 8 小时）
         ↓
后续请求在 HTTP Header 中携带 Authorization: Bearer <token>
         ↓
后端通过 get_current_user() 解析 Token 获取当前用户身份
         ↓
管理接口通过 require_admin() 校验角色是否为 admin
```

### 4.4 API 设计规范

- 遵循 RESTful 设计原则
- 基础路径：`/api`
- 请求格式：`application/json`
- 成功响应：直接返回 JSON 对象或数组
- 错误响应：`{"detail": "错误描述信息"}`
- 状态码：200（成功）、400（参数错误）、401（未认证）、403（权限不足）、404（资源不存在）

### 5.7 风险预警模块（RISK）

| 功能编号 | 功能名称 | 描述 | 访问权限 | 状态 |
|:--------:|----------|------|:--------:|:----:|
| RISK-01 | 风险预警检查 | 综合分析志愿数量、冲稳保比例、重复院校、分数倒挂等问题，生成预警和建议 | 登录用户 | ✅ |

**风险检测维度与规则：**

| 维度 | 规则 | 预警条件 | 建议 |
|:----:|------|----------|------|
| 志愿数量 | 总数检查 | 总数 < 6 → 数量偏少；总数 = 0 → 无志愿 | 建议至少填报6个 |
| 冲稳保比例 | 基于分数差分类 | reach=0（无冲刺）；safe=0（无保底）；stable=0（无稳妥） | 建议按2:4:4比例 |
| 冲刺比例 | 过高的风险控制 | reach_pct > 50% | 请合理控制风险 |
| 保底比例 | 保底充足度 | safe_pct < 20% | 建议提高到30-40% |
| 重复院校 | 重复性检查 | 存在相同university_id | 存在重复院校，请检查 |
| 分数倒挂 | 顺序合理性 | 高分院校排在低分院校后面 | 存在分数倒挂，请调整顺序 |
| 成绩缺失 | 数据完整性 | 用户尚未录入成绩 | 请先录入高考成绩 |

**分类规则（分数差 = 用户分数 − 高校最低录取分）：**

| 分类 | 条件 | 建议比例 |
|:----:|:----:|:--------:|
| 冲刺 | 分数差 < 0 | 约20% |
| 稳妥 | 0 ≤ 分数差 < 30 | 约40% |
| 保底 | 分数差 ≥ 30 | 约40% |

```sql
CREATE PROCEDURE sp_search_university_by_score(IN p_score INT)
BEGIN
    SELECT id, name, ranking, description, min_score, province
    FROM university
    WHERE min_score IS NOT NULL 
      AND min_score BETWEEN p_score - 50 AND p_score + 20
    ORDER BY min_score DESC, ranking ASC;
END;
```

3. **SQL注入风险**：使用 SQLAlchemy ORM 查询替代原生 SQL 字符串拼接，如必须使用原生 SQL，确保所有参数通过 bindparam 传递，对 keyword 进行输入校验和过滤。预计工时：2小时。

## 11. 项目总结与展望

### 11.1 项目成果总结

经过三天（7月8日-7月10日）的极速冲刺开发，"你说都队"团队成功完成了高考志愿辅助填报系统最小可行产品（MVP）的开发。系统涵盖：

- **10张数据表**：完整覆盖用户、高校、专业、成绩、志愿、录取数据等核心业务实体
- **30+个API端点**：覆盖7个业务模块，支持完整的用户端和管理端操作
- **16个前端页面**：毛玻璃设计风格，适配桌面端和移动端
- **112所高校 + 178个专业 + 150条录取数据**：覆盖200-700分全梯度

### 11.2 技术亮点

1. **智能推荐引擎**：基于存储过程的估分匹配算法，按"冲刺/稳妥/保底"三级分类推荐
2. **多维风险预警**：从志愿数量、冲稳保比例、重复院校、分数倒挂四个维度分析
3. **全流程闭环**：从成绩录入→估分推荐→志愿填报→风险预警，形成完整链路
4. **角色权限分离**：前后端双重校验（路由守卫 + API依赖注入）

### 11.3 待改进方向

1. **密码加密**：引入 bcrypt 哈希存储（已列入P1修复计划）
2. **推荐算法优化**：引入基于位次的匹配，提高推荐精准度
3. **分页机制**：高校列表等大数据量接口增加分页（已列入P2修复计划）
4. **前端权限控制**：添加路由守卫和403错误处理（已列入P2修复计划）
5. **性能优化**：修复N+1查询问题，批量操作使用批量SQL（已列入P2修复计划）
